# Publishing -- how content in this repo reaches a host

One pipeline. Anything outside it does not ship: two hand-built pages in
`standalone-pages/` were published to prod by hand on 2026-08-30, staged by
nothing, and answered 404 from the blog->media move (2026-09-05) until they
became posts on 2026-09-10 (fleet-ops ticket 0059).

## Where content lives, what renders it, where it lands

| content | source | rendered by | lands at |
|---|---|---|---|
| a post | `profiles/<oper>/blog/<slug>.md` | `convert.sh` -> `media/<oper>/dist/blog/<slug>/index.html` (+ `og.jpg`, `tile.png`), listed in `dist/blog_manifest.json` with `kind: post` | `https://<oper>.media.tcos.us/blog/<slug>/` |
| a thesis | `profiles/<oper>/thesis/<slug>.md` (same header block) | the same renderer, `kind: thesis` -> `media/<oper>/dist/thesis/<slug>/` | `https://<oper>.media.tcos.us/thesis/<slug>/` |
| a gallery | `media/<oper>/dist/gallery/<item>/item.card.v1.yaml` and the files beside it | `media/bin/media-item.py` | `https://<oper>.media.tcos.us/gallery/<item>/` |
| the resume | `profiles/<oper>/dist/resume.md`, which `convert.sh` builds from the profile's source | `bin/render-resume.py`, into the stage at deploy | `https://<oper>.media.tcos.us/resume` (+ `.pdf`, `.md`, `.txt`) |
| the hubs and the blog redirects | `profiles/*/profile.json` -> `dist/people.json`; `bin/blog-redirect-worker.py` -> `dist/_worker.js` | `convert.sh` | `media.tcos.us`, `blog.tcos.us`; every `<oper>.blog.tcos.us` is a redirect to that operator's media host |

`<oper>` is the profile's `roster_slug`; the media host is its
`meta.media_routing`. Lab is the same host names under `.lab.tcos.us`
(`spencer.media.lab.tcos.us`), served from pve container 107 behind
haproxy (fleet-ops `pve/haproxy/haproxy.cfg`).

## URL kinds, not tags

Every page on a media host lives under its kind -- `/blog/<slug>/`, `/gallery/<item>/`, `/thesis/<slug>/` -- as a directory with `index.html` and its images beside it (operator, 2026-09-11: "url path names instead of tags"). The old `/posts/<slug>.html` and bare `/<item>/` URLs redirect: on prod through the `_redirects` file `deploy.sh` writes into the stage (one explicit line per gallery, never a catch-all), on lab through the same rules in fleet-ops' haproxy.

## A post, or a thesis

`profiles/<oper>/blog/<slug>.md`. Line 1 is the title (`# ...`). Line 2
carries the date (`**Date:** 2026-08-30`): `convert.sh` reads the date from
line 2, then from the filename, then from the file's mtime. Then
`**Author:**`, `**Tag:**`, a `---` rule, the prose. Markdown only --
blockquotes for callouts, fenced code, no raw HTML. The filename is the
slug is the URL. A thesis is the same file under `profiles/<oper>/thesis/`.

Commit the `.md` alone. Everything under `media/*/dist/posts/` and `dist/`
is a tracked build output that `hee release -cut` renders and commits into
the release commit, where the release PR shows what ships.

## Lab, then prod

    hee release -lab -repos resume            # builds (convert.sh), pushes every surface to lab
    # review at https://<oper>.media.lab.tcos.us/posts/<slug>.html
    hee release -cut -repos resume -yes       # release commit + PR; approving and merging it is the sign-off
    hee release -promote -repos resume -yes   # prod, tags, GitHub Release; runs under hee cred (cloudflare-tcos-www)

The surfaces and their commands are `release.card.v1.yaml`. Promote is the
operator's act. Nothing deploys on merge: a merged `.md` is on no host until
`-lab` runs.

## Gates on the way (`media/bin/deploy.sh`)

- lab and promote: the stage must carry every post and thesis the build manifest lists
  for the operator (`<kind>/<slug>/index.html`) -- a stale checkout is refused, not pruned live.
- promote only: every media item's card says `consent: approved`;
  `hee check all` passes; no git conflict markers in the stage; every image
  carries the org branding, every generated image its provenance.

## Redirects

A blog host stays alive as a redirect only. Prod: `dist/_worker.js`,
generated by `bin/blog-redirect-worker.py` from `people.json`, shipped with
the `resume-pages` surface. Lab: the same rules by hand in fleet-ops
`pve/haproxy/haproxy.cfg`. Old post URLs, the old resume URLs, and a
top-level page name all map to `/blog/<slug>/` on the media host; anything
else goes to the media root.
